# Exercício 08 — Quiz relâmpago de Git e GitHub

Responda e depois confira.

1. Git e GitHub são a mesma coisa?
2. O que é um repositório?
3. Qual é a ordem correta do ciclo básico de trabalho?
4. V ou F: uma boa mensagem de commit deve explicar exatamente o que mudou, não só dizer "mudanças".
5. O que é a branch `main`?
6. Por que criar uma branch separada antes de testar uma ideia arriscada?
7. O que significa "dar merge" em uma branch?
8. Um conflito de merge é motivo de pânico?
9. Para que serve o arquivo `.gitignore`?
10. O que é um Pull Request?

<details>
<summary>Ver respostas</summary>

1. **Não.** Git é um programa instalado no seu computador que controla versões; GitHub é um serviço online que hospeda repositórios Git.
2. Uma pasta de projeto que guarda todos os arquivos **e todo o histórico de mudanças** deles.
3. Editar → adicionar ao commit (`add`/stage) → commitar (`commit`) → enviar (`push`).
4. **Verdadeiro.**
5. A branch principal: a versão "oficial" e estável do projeto (antigamente também chamada `master`).
6. Para experimentar sem afetar a versão principal.
7. Juntar as mudanças de uma branch em outra (normalmente na `main`).
8. **Não.** Conflitos são normais em projetos colaborativos e se resolvem escolhendo qual versão manter.
9. Para dizer ao Git quais arquivos **não** devem ser versionados (senhas, arquivos temporários, dados sensíveis).
10. Um pedido para que as mudanças de uma branch sejam revisadas e integradas na branch principal.
